Software Requirements Specification

College Attendance Management System (v9.0)

Thakur College of Engineering & Technology

1. Introduction

1.1 Purpose

This Software Requirements Specification (SRS) document details the complete functional, non-functional, security, and architectural requirements for the College Attendance Management System developed for Thakur College of Engineering & Technology (TCET).

1.2 Scope

The system provides an enterprise-grade digital solution replacing paper-based attendance registers with automated session tracking, real-time role-based access control (Superadmin, Department Admin, Faculty, Student), A3 Landscape monthly matrix report generation, customizable signature blanks, and cross-platform native Android mobile execution.

1.3 Definitions and Abbreviations

  • SRS: Software Requirements Specification
  • TCET: Thakur College of Engineering & Technology
  • 2FA: Two-Factor Authentication
  • PWA: Progressive Web Application
  • HOD: Head of Department
  • JWT: JSON Web Token

2. Overall Description

2.1 Product Perspective

The Attendance System operates as a web-based and native Android application backed by a Node.js Express REST API server and a MongoDB Atlas Cloud database cluster.

2.2 User Classes and Roles

Role Privileges & Responsibilities
Superadmin Full system governance, department creation, department admin assignment, system directory control, and master data reset.
Department Admin Department-scoped management of faculty members, student enrollment, lecture schedules, substitute faculty assignment, and attendance matrix report generation.
Faculty Schedule lecture sessions, mark live student attendance (Present/Absent), edit roster sheets, and view subject attendance logs.
Student View individual subject attendance logs, track overall percentage performance, and review detailed session dates.

2.3 Operating Environment

  • Web Client: Modern web browsers (Chrome, Edge, Safari, Firefox).
  • Mobile Client: Android 8.0+ (Native APK via Capacitor runtime) and iOS (PWA Safari).
  • Backend Runtime: Node.js v18+ with Express framework.
  • Database: MongoDB Atlas Cloud Engine (v6.0+).

3. System Features & Functional Requirements

3.1 Multi-Factor Authentication & Security

The system implements a 2-step security verification mechanism. Upon entering valid credentials, users receive a 6-digit security code verification step before gaining JWT-authenticated access. Session auto-logouts trigger after 5 minutes of inactivity.

3.2 Lecture Scheduling & Substitute Management

Admins and faculties can schedule lecture sessions with custom or pre-set time slots (e.g. 9:30 AM to 11:30 AM). Department Admins can assign substitute faculties to conducted sessions when primary faculties are unavailable.

3.3 Attendance Marking & Live Register Sheet

Faculties load student rosters filtered by department, branch (e.g., SD), and batch (e.g., Batch-5). Radio controls allow 1-click Mark All Present and Mark All Absent options with instant database persistence.

3.4 Monthly Matrix Attendance Reports & Custom Signatures

Generates 28-column monthly attendance sheets formatted according to institutional standards. Includes a 7-slot customizable signature block editor (Prepared By, Checked By, Verified By, Reviewed By, Approved By, Vice Principal, Principal) supporting live 2-way DOM sync, PDF export (A3 Landscape), and CSV/Excel exports.

3.5 Master Data Reset & Cleanup

Superadmins can execute targeted cleanups (Attendance Only, Lectures Only, Users Only) or Master Factory Reset protected by a Master Password (RESET@2026) and capital letter confirmation.

4. Database Schema & REST API Specification

4.1 Database Models

  • User Schema: Stores name, email, hashed password (bcryptjs), role, department array, and student details (roll number, branch, batch).
  • Department Schema: Stores degree (BE, BVOC, B.Tech), branch, department name, code, and description.
  • Lecture Schema: Stores subject, department, branch, batch, primary faculty, substitute faculty, date, time slot, and status (scheduled, completed, canceled).
  • Attendance Schema: Stores lecture ID, student ID, status (present/absent), date, time slot, and marker user reference.

4.2 Key REST API Endpoints

Method Endpoint Access Role Description
POST /api/auth/login-step1 Public Validate email/password and issue temporary security token.
POST /api/auth/verify-security Public Verify 6-digit security code and issue JWT access token.
GET /api/lectures Authenticated Fetch scoped lecture sessions.
POST /api/attendance/mark Faculty Submit live attendance roster records.
GET /api/reports/monthly-matrix Admin Generate monthly matrix data sheet.
POST /api/system/reset Superadmin Execute protected data reset operations.

5. Non-Functional Requirements

  • Performance: Page load times under 1.2s; report rendering under 800ms.
  • Security: Passwords salted with bcrypt (10 rounds); HTTP headers set via Helmet middleware (XSS, NoSniff, Frame-Options DENY).
  • Availability: 99.9% uptime backed by MongoDB Atlas Cloud Cluster.
  • Maintainability: Modular architecture separating models, routes, middleware, and public static client assets.
