1. Product Requirements Document (PRD)

1.1 Executive Summary & Vision

The TCET Attendance Management System is an enterprise web and native mobile solution engineered to digitize, streamline, and secure academic session attendance tracking across multi-department engineering colleges.

1.2 Business Goals & Problem Statement

  • Problem: Traditional paper registers lead to lost physical sheets, proxy attendance, delayed monthly HOD summary reports, and manual calculations prone to human error.
  • Goal: Eliminate physical paperwork by 100%, automate monthly A3 Landscape matrix reports with instant PDF/Excel exports, and enforce 2-step verification security across 4 distinct user roles.

1.3 Target Audience & User Personas

  • Superadmin: College IT Directors requiring overall system governance, department creation, and database maintenance.
  • Department Admin: HODs and Department Coordinators managing faculties, student enrollments, substitute schedules, and monthly matrix verification.
  • Faculty: Lecturers needing fast, mobile-friendly live attendance marking (Present/Absent).
  • Student: Undergraduates tracking subject-wise attendance logs and overall percentage benchmarks.

2. Functional Specification Document (FSD)

2.1 Authentication & 2-Step Verification Flow

User Interaction Path: User enters email + password → System validates credentials → Generates 6-digit security code → User enters code on security.html → Issues final JWT token & redirects to role dashboard.
  • System enforces maximum 15 login attempts per 15-minute window per IP.
  • Automatic logout executes after 5 minutes of client inactivity.

2.2 Lecture Scheduling & Visual Time Slot Picker

Form contains visual dual time pickers (Start Time to End Time) converting 24-hour inputs to AM/PM strings (e.g. 9:30am to 11:30am), alongside quick preset chips (🌅 9:30 AM - 11:30 AM, ☀️ 11:30 AM - 1:30 PM, etc.).

2.3 Attendance Marking Behavior

  • Faculty selects a scheduled lecture → System fetches registered students filtered by branch and batch.
  • Selecting "Mark All Present" sets all student radios to present instantly.
  • Submitting form sends POST /api/attendance/mark payload and marks lecture status as completed.

2.4 7-Slot Signature Customization Engine

Admin report settings panel contains 7 signature cards (Prepared By, Checked By, Verified By, Reviewed By, Approved By, Vice Principal, Principal). Modifying panel input updates the report DOM in real-time, and inline contenteditable edits sync back to input fields and save in localStorage.

3. Non-Functional Requirements (NFR)

3.1 Performance Goals

  • Page Load Time: Initial page render under 1.2 seconds over 3G/4G networks.
  • API Response Time: Sub-200ms latency for login and attendance roster queries.
  • PDF Export Compilation: Client-side PDF generation completed under 1.5 seconds for 28-column matrix sheets.

3.2 Security Protocols & Constraints

  • Password Hashing: Passwords salted and hashed via bcryptjs (10 rounds).
  • HTTP Security Headers: Enforces X-Frame-Options: DENY, X-Content-Type-Options: nosniff, X-XSS-Protection, and Strict-Transport-Security.
  • JWT Encryption: 256-bit signed JSON Web Tokens stored securely in browser session.

3.3 Scalability & Availability Target

  • Target User Load: Configured to handle 5,000+ concurrent students and faculties.
  • Availability: 99.9% uptime backed by MongoDB Atlas Cloud Replica Sets.

6. Project Management & Deployment Manual

6.1 Product Backlog & Release Roadmap

  • Sprint 1 (Core Auth & Database): MongoDB Atlas schema design, JWT authentication, 2-step verification security.
  • Sprint 2 (Admin & Faculty Portals): Department management, student enrollment, lecture scheduling, visual time slot picker.
  • Sprint 3 (Attendance & Reports): Live roster marking, monthly matrix report generator, A3 PDF export, 7-slot signature customizer.
  • Sprint 4 (Mobile & Cloud Deployment): Capacitor native Android APK build, Render.com cloud deployment, GitHub CI/CD pipeline.

6.2 Deployment & DevOps Manual

1. Render.com Hosting Deployment

  • Connect GitHub repository hiteshsuthar911/attendance-management-system on Render dashboard.
  • Set Build Command: npm install | Start Command: npm start.
  • Set Environment Variables: NODE_ENV=production, MONGODB_URI, JWT_SECRET, MASTER_RESET_PASSWORD=RESET@2026.

2. Native Android APK Compilation

  • Run Capacitor sync: npx cap copy android && npx cap sync android.
  • Open Android Studio: npx cap open android.
  • Click Build → Build Bundle(s) / APK(s) → Build APK(s). Compiled file generated in android/app/build/outputs/apk/debug/app-debug.apk.
